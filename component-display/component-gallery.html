Table Architecture (per En_Table rule book CANONICAL):

  • EncTableContainer: Horizontal scroll ownership, sticky header context, density binding (Compact by default).
  • EncTableHeaderCell: Column label, non-interactive by default. Alignment: Left (text), Center (status/icons), Right (numeric).
  • EncTableRow: Represents ONE record. States: default, hover, selected, disabled.
  • EncTableCell: Content container only. Hosts DS components (EncTag, EncIconButton, EncAvatar, EncCheckbox).

Governed metadata label for status, sentiment, lifecycle, or categorical metadata.

Role / Intent: Compact metadata label for status or categorization (read-only).

Use when: Status badges, categories, filters in lists.

Do NOT use when: As a button or action; for chart legends; for primary CTAs.

EncButton (enc-action-primary / enc-action-secondary)

Primary/secondary action button. States: default, hover, focus, disabled. Size variants per DS: Lg, Sm, Mini (not bound in enculture.css; shown: default).

Role / Intent: Primary or secondary action button.

Use when: Main CTA (primary); secondary actions like Cancel, Back (secondary).

Do NOT use when: Navigation link (use <a>); icon-only (use EncIconButton); toggle (use EncToggle). Do not use enc-btn or enc-btn-primary (forbidden).

Stable props: class enc-action-primary or enc-action-secondary; disabled; visible label.

Governance: enc-btn/enc-btn-primary forbidden; focus visible; disabled not focusable; label required.

Destruction warning: For destructive actions (delete, remove, irreversible), use enc-action-secondary and always show confirmation (modal or step) before submit; do not use enc-action-primary for destructive without confirmation.

Success states: After success, use EncToast (Success) or EncTag for status; disabled state for loading; no built-in success visual on the button.

Do not use for:
  • enc-btn or enc-btn-primary (forbidden; use enc-action-primary/secondary only)
  • Status badge or label (use EncTag)
  • Primary destructive action without confirmation flow
  • Dashboard or analytics-only custom buttons that bypass DS

EncIconButton

Icon-only action button (Lucide). Accessible label required. Sizes: Icon.Sm, Icon.Md, Icon.Lg.

EncTable — Table Component

Composition pattern for structured data display. Composed of EncTableContainer, EncTableHeaderCell, EncTableRow, EncTableCell. Compact density by default.

Role / Intent: Structural composition pattern for displaying tabular data. Tables communicate STRUCTURE, not emotion.

Use when: Displaying structured data, lists with multiple columns, admin tables, data tables.

Do NOT use when: Layout (use EncContainer, EncSection); single column lists (use EncListRow); feature-specific table components.

Architecture: Tables are composed ONLY of: EncTableContainer, EncTableHeaderCell, EncTableRow, EncTableCell. There is NO monolithic EncTable component.

Stable props: Semantic structure (container → header → rows → cells); density binding (compact by default); row states (default, hover, selected, disabled).

Governance: Status/metadata MUST use EncTag (success/warning/error/neutral). Data/comparison MAY use Dashboard Pastels (analytics only). Text MUST use grayscale tokens only. Filters/search/pagination live OUTSIDE table. Legacy teal-based tables are NON-COMPLIANT.

Do not use for:
  • Feature-specific table components (use composition pattern)
  • Teal for status (legacy, non-compliant — use EncTag)
  • Brand Purple in tables (forbidden)
  • Filters/search inside table (live OUTSIDE table)
  • Raw badges/chips (use EncTag)
  • Custom buttons in cells (use EncIconButton)

Color Swatches — Background Colors

All Enculture DS color tokens for backgrounds, surfaces, and semantic states. Use var(--en-*) tokens only.

Role / Intent: Reference for all DS color tokens.

Use when: Selecting colors for backgrounds, surfaces, borders, text (via tokens).

Do NOT use when: Raw hex/rgba values; colors not defined in DS tokens.

Stable props: CSS custom properties (var(--en-*)) only.

Governance: All colors must use DS tokens; no raw color values.

Do not use:
  • Raw hex colors (e.g., #a246f0) — use var(--en-primary-brand-500)
  • Raw rgba values — use DS tokens
  • Colors not defined in DS (flag as gap)

Semantic Color Combinations (WCAG AA Compliant)

Enculture DS semantic combinations ensure WCAG 2.2 AA compliance (minimum 4.5:1 contrast ratio). Follow these combinations strictly.

Semantic Combination Rules:

  • Primary Brand 500/700: Background → Text: White (Text.OnPrimary). WCAG AA: 4.5:1 contrast ratio.
  • Success 500: Background → Text: White (Text.OnPrimary). WCAG AA: 4.5:1 contrast ratio.
  • Error 500: Background → Text: White (Text.OnPrimary). WCAG AA: 4.5:1 contrast ratio.
  • Light backgrounds (grey-0, grey-20, grey-50, grey-100): Text: --en-grey-800 (Primary Text). WCAG AA: 4.5:1 contrast ratio.
  • Dark backgrounds (grey-600, grey-700, grey-800, grey-1000): Text: White (--en-grey-0). WCAG AA: 4.5:1 contrast ratio.
  • Medium backgrounds (grey-200, grey-300, grey-400, grey-500): Text: --en-grey-800 for light, White for dark. Test contrast ratio.

WCAG Note: All Enculture DS semantic combinations meet WCAG 2.2 AA standards. Do not override these combinations. If custom combinations are needed, verify contrast ratio ≥ 4.5:1 for normal text, ≥ 3:1 for large text.

Design System Semantics — Visual References

This page demonstrates Enculture DS as a product page. All semantics, spacing, colors, and components follow DS governance rules.

Role / Intent: Visual reference demonstrating Enculture Design System semantics applied to a product page.

Key DS Semantics Applied:

  • Semantic Classes: Use .enc-* classes (e.g., .enc-main-container, .enc-card, .enc-action-primary). These are hooks in enculture.css, not styled directly.
  • Design Tokens: All colors, spacing, radius, typography use var(--en-*) tokens. No raw px/rem/hex values.
  • Density System: Compact mode via data-density="compact" on container. Controls height, spacing, radius automatically.
  • Semantic Color Combinations: Primary brand 500/700 → White text (Text.OnPrimary). Light backgrounds → Grey-800 text. Dark backgrounds → White text.
  • WCAG Compliance: All semantic combinations meet WCAG 2.2 AA (4.5:1 contrast ratio minimum).
  • Responsive Design: Breakpoints aligned with EncContainer (Sm 720px, Md 960px, Lg 1200px). Padding scales: Desktop 20px, Tablet 16px, Mobile 12px.
  • Spacing: Use var(--en-space-*) tokens. No arbitrary spacing. Section gaps: --en-space-2xl (48px). Component gaps: --en-space-xl (32px).
  • Typography: Use var(--en-font-size-*) and var(--en-font-family-base). Responsive scaling handled by enculture.css.

Governance: This page follows Enculture DS rules strictly. No custom styling outside DS tokens. No new components or variants. All visual properties resolve from DS tokens.

Do NOT:
  • Use raw CSS values (px, rem, hex) — use DS tokens
  • Style .enc-* classes directly — use scoped selectors or gallery-specific classes
  • Create new color combinations — use DS semantic combinations only
  • Override DS spacing — use density tokens
  • Break WCAG compliance — follow semantic combinations

Typography — Font Styling

All Enculture DS typography tokens: font families, sizes, weights. Use var(--en-font-*) tokens only.

Role / Intent: Reference for all DS typography tokens.

Use when: Setting font sizes, families, weights (via tokens).

Do NOT use when: Raw px/rem values; fonts not defined in DS tokens.

Stable props: CSS custom properties (var(--en-font-*)) only.

Governance: All typography must use DS tokens; no raw font values.

Do not use:
  • Raw px values (e.g., 16px) — use var(--en-font-size-md)
  • Raw rem values — use DS tokens
  • Font families not in DS (use var(--en-font-family-base))
/* Use tokens, not raw values */ font-family: var(--en-font-family-base); font-size: var(--en-font-size-md); font-weight: 600; /* Use numeric weights: 400, 500, 600, 700 */
